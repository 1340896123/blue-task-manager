## 1. 用户目标与产品边界

用户需要快速确认机器的真实资源状态，查找占用异常的进程，查看进程、用户、启动项与服务信息，并能安全启动和结束自己的任务。产品使用参考图的桌面信息结构，采用 Windows 蓝色风格，不能提供演示数值、静态伪曲线或没有实际作用的操作入口。

本版交付完整可运行的用户态任务管理器。核心能力覆盖七个业务导航页与设置；不承诺 TaskExplorer 的驱动级线程/句柄分析、调试注入、远程主机管理、内核保护绕过、历史全机追溯、逐进程 GPU/网络追踪。未接入的指标必须有显式能力状态，不能以 0 填充。

## 4. 数据正确性要求

1. CPU 由累计内核/用户时间的相邻有效样本差计算；进程 CPU 使用整机逻辑处理器归一化。第一帧或计数回退时为预热/未知。系统 CPU 根据 GetSystemTimes 计算，不能简单加总可读进程 CPU。
2. 内存显示工作集与物理内存来源，单位统一。只读到部分进程时，不能把这些进程的总和称为全机内存。
3. GetProcessIoCounters 代表进程 I/O，包括缓存、文件、设备等；列名使用“I/O”，不得标为物理磁盘吞吐或活动时间。
4. 逐进程网络与 GPU 不具备本版采集源时，返回 `null`，在界面显示“—”并提供“未接入逐进程采集”等原因。0 仅表示真实采样结果为零。
5. 曲线按实际时间戳绘制；断流保留缺口或中断状态。展示最后更新时间、暂停/断连状态及采样周期。
6. PID 是瞬时地址，进程身份由 PID+原始创建 FILETIME 构成；创建时间使用十进制字符串避免 JavaScript 精度损失。
7. 每个可缺失的指标应有可用状态/原因。拒绝访问与不支持不影响其他进程刷新。

## 5. 交互与质量要求

- 按钮、表头排序、选择、搜索、导航、设置均可键盘使用；有可见焦点、输入标签、当前导航语义和对话框焦点管理。
- 蓝色热度不能是唯一信息渠道；始终显示数值和单位。刷新不清空当前焦点与输入，不让屏幕阅读器持续朗读整个进程表。
- 首次加载、预热、空列表、失败、断连、暂停有不同状态。后台接口未响应时不无限转圈。
- 表格采用虚拟滚动或等效的有界渲染策略；进程数量增大时，不一次挂载数千可交互单元；真实采样任务串行，不重叠采样。
- 非破坏性导航和读取无确认流程；结束进程有明确一次确认。后台不能接受只带 PID 的结束操作。
- 不要求网络才能运行；字体/图标在本地提供，不引入线上字体请求。
