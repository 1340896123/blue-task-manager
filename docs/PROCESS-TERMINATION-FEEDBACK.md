# 单进程结束反馈

日期：2026-11-02。用户要求：结束成功直接提示成功；不成功时继续显示当前结束进程页面。

## 行为与实现边界

- 保留结束前的身份、影响说明与一次确认。提交期间禁用重复操作。
- 单进程结束接口返回 `completed === true` 时，自动关闭结束弹窗，使用现有全局成功通知展示进程名称、PID 与真实确认结果，并刷新数据。
- HTTP/Windows 错误保留当前弹窗、目标身份及错误；未确认退出（`completed` 为 false/null）继续显示结果与关闭入口，不显示成功、不自动重试。
- 成功只能依据后端同句柄 `WaitForSingleObject` 的确认；快照中的目标消失或 `alive=false` 不能证明本次操作成功。
- 复用现有 Modal、toast、成功图标及语义 Token，不新增视觉 Token、依赖、协议或原生接口。完整进程树保留逐项结果，优先级/效率模式沿用既有反馈。

## 阶段一检查

独立子代理只读检查确认：`ProcessActionDialog` 在所有结束响应后保留 result，因此成功弹窗仍存在；随后真实快照移除目标，导致页面同时出现红色退出提示。最小修复是为单进程确认成功增加回调，由 `ProcessWorkspace` 关闭弹窗并发送现有通知。后端真实确认链无需修改。

UI/UX Pro Max 定向检索 `success feedback error recovery --domain ux` 命中 Success Feedback、Error Recovery、Error Feedback：成功明确通知，失败在原上下文可读。沿用现有 Windows 蓝色规范及原生 dialog 焦点管理。

## 本轮验收

1. Web 类型检查、生产构建、C# Release 构建；核对成功严格判断与非成功保留分支。
2. 生产浏览器与正式 Electron 只结束测试专用进程：先取消并确认仍存活，再确认结束，断言成功 toast、弹窗自动消失、真实进程退出及列表移除。
3. 对测试专用目标发送错误创建身份到真实后端，验证真实 409、目标存活、错误弹窗保留、无成功通知；不伪造响应或采样数据。
4. 回归 `docs/ACCEPTANCE.md` 的受影响 A01/A09/A10/A11/A16/A18 与 B05；截图、复现命令和执行限制记录在专项结果中。未确认退出依赖真实 Windows 超时，无法稳定触发时记录为仅源码核对。
