# Takao 1.1：日常使用闭环与性能

日期：2026-10-23。状态：本轮实施规范；功能是否完成以最终源码与 `ACCEPTANCE-RESULTS.md` 为准。本文件扩展1.0范围，旧文档“只读/不在范围”不能豁免本轮已明确扩展项。

## 1. 目标与证据

主要用户是本机Windows日常使用者：机器变慢时找出原因、确认目标、执行恰当操作，再确认机器和目标的实际状态。熟练用户需要少重复输入、保留上下文、键盘和右键加速；不要求用户理解采样器、PID复用或内部缓存。

已知事实：用户要求真实Win32链路、参考布局、Windows蓝色Token、性能、尽量补齐功能、自治实施与真实E2E。源码审计发现当前已有虚拟列表和PID+FILETIME保护，但无树、右键/双击、路径入口、导出、优先级和服务动作；详情仅保留打开时快照；导航清空查询/排序；只有密度在localStorage中保存；每次轮询重新传输/反序列化完整快照。`Win32Collector`还为内存另开强权限句柄并同步读取新进程文件版本/用户SID。

性能基线（主代理在本机实测，原始结果 `output/performance/v1-baseline.json`，不提交完整机器清单）：883进程、28逻辑核；完整快照1,262,445字节；12次读取p50 54.7ms/p95 81.9ms；10秒真实UI轮询时Host单核14.77%/整机0.527%，private69.5MB/工作集113.7MB；表中渲染28行、DOM1089、JS堆17.5MB。本机真实GPU Engine计数器可读，1632个有效实例；本轮必须尝试CsWin32 PDH接入，不能继续用未研究为由恒null。当前主机非管理员，服务成功链路依赖可操作权限，拒绝访问链路可直接验收。

场景与频率是从已有产品任务推断，未开展用户访谈，不声称用户研究或量化效率提升。按About Face把目标、对象、反馈、恢复连成闭环；视觉沿用既有MASTER，不重新生成营销式设计系统。

## 3. 对象与交互规则

- 主导航保持参考图。进程树是现有列表的显示模式，不新增迷惑用户的独立进程页面。关系以当前同快照父PID+创建先后为依据；父进程已退出/身份不可读时作为孤立根，不伪造可靠谱系；循环保护且排序作用于同层。树可见行仍虚拟化。
- 详情为可关闭的宽面板/大对话框，概览、关联服务、网络连接按需加载，返回恢复列表位置。读取失败保留上次值与时间。长路径可选择复制与折行，不撑破布局。
- 单击选择；双击打开详情；右键选中被点击身份后打开菜单，菜单对目标使用不可变引用，刷新不会把动作挪给另一进程。Shift+F10是键盘等效入口。右键不是唯一入口，工具栏“更多”和详情动作可发现。
- Ctrl+F搜索、F5刷新、Ctrl+N运行新任务、Enter详情、Delete打开单目标结束确认、Space/按钮冻结显示；输入框/编辑控件内不劫持快捷键，Escape按最上层关闭。快捷键帮助可在设置访问；快捷键不绕过确认或后端校验。
- 冻结显示只锁定列表/所见数值与其时刻，不暂停系统采样和性能历史。期间显示“显示已冻结 · 时刻”及继续按钮，执行前仍向实时后端验证身份。原有“暂停采集”保留为设置中的独立行为，状态文案不可混同。
- 写操作忙时防重复，成功以实际读回结果为准；StartService/TerminateProcess接受请求不等于目标最终完成。服务/树部分成功保留逐项结果；超时先查实际状态，不盲目重试。不可恢复动作不提供假撤销。
- 服务重启需一次明确确认对象和短暂不可用；遇到依赖运行阻止停止，显示Windows原因，绝不静默停止依赖。高优先级/树终止分别有具体影响说明。只读复制/导航/导出不弹确认。
- 搜索无匹配、首次加载、当前来源真实空、无权限、采样预热、断流、已退出、冻结、后台节流有不同文字；未知保留null，不能转0。读屏只通知动作/连接变化，不每秒播报整个列表。

## 4. 系统接口与实施顺序

1. 文档阶段先提交本规范、契约、Token和验收增量。
2. 核心原生阶段：先修内存权限/缓存/ETag/偏好，再详情/文件动作/优先级/树操作/TCP-UDP、SCM动作；每个能力有原生错误与来源。不使用System.Text.Json。独立提交和真实API检查。
3. 扩展遥测阶段：PDH GPU/磁盘、逐适配器、系统提交信息及按需图标。GPU/PDH初始化必须后置异步，不能把当前约0.9秒基础就绪拖到数秒；query未就绪时基础进程/CPU/内存先可用。独立提交和真源/开销检查。
4. UI阶段：复用Token组件与虚拟表格，先冻结/上下文持久化/详情/菜单，再各页联动与真实资源选择器。保留原始DTO明确类型，统一client调用；不得直接赋予renderer Node能力。该阶段独立提交、类型与构建检查。
5. E2E阶段：真实专用父子树、TCP/UDP端点、文件选择/文件动作、原生优先级读回、重启持久化、服务拒绝、PDH与性能对照、所有导航和真实Electron生命周期。仅结束测试自行创建的身份；完成修复再独立提交。主代理可按依赖拆成额外阶段，仍顺序交接并提交。

一个阶段代理写业务代码时，其余阶段不并发修改业务代码。每个阶段需向下一阶段交接实际合同与平台限制。

## 5. 性能预算与测量

预算是本机同规模真实样本的工程目标，不虚报为已达成SLA。记录CPU归一化口径、PID数量、采样间隔、窗口状态、测量时长与p50/p95；至少预热两帧并测30秒。与上文基线同条件比较，超过目标须查原因并修复或在验收中列出实际代价。

| 方面 | 目标与规则 | 验证 |
|---|---|---|
| 采样/CPU | 1秒采样串行、无重叠；约900进程整机Host平均CPU目标≤1%，加入GPU后的开销单列；稳定期采样p95目标≤500ms | 真实PID数量/CPU时间差与单调计时，禁用假数据压测 |
| HTTP | 相同表示使用If-None-Match→304空体，保持内存旧对象；不因304清空数据/失联；暂停或同帧重复GET不重复1.26MB，冻结不阻止后台新样本 | 响应体/ETag/304统计，修改设置/历史/警告也改变版本；不缓存token |
| 列表 | 保持当前虚拟化，挂载行≈视口+overscan；稳定identity key，memo只用于实测贵组件；不在每秒列头/列表重建无关菜单/设置 | 真实列表DOM行数、React/浏览器profile和JS堆；记录输入/切页响应，目标<100ms |
| 慢字段 | 文件版本按规范化路径+文件mtime缓存，SID解析按SID缓存（有界）；新身份元数据预算化补全，已有值不每秒重读；详情/连接≤2秒按需缓存 | 新进程密集出现时仍先给基础快照；未读字段用loading/notCollected，缓存限制可检查 |
| 网络/PDH | 网卡和PDH query复用，每帧一次批量读取；不按PID另开PDH query；不把1632 GPU实例明细每帧传给UI | 采样耗时/句柄数/响应大小前后对照；原生query在关闭释放 |
| 隐藏/冻结 | document.hidden轮询≥5秒，可见立即补最新；冻结UI不阻断全局采样。每个client至多一个飞行请求 | Electron最小化/恢复与浏览器visibility行为，sampleId仍前进 |
| 有界资源 | 性能历史≤120真实点、会话身份≤20,000；所有新增缓存有上限/TTL；详情请求取消或忽略过期结果 | 连续运行并反复详情/切页，句柄/内存不无界增长；记录实际Host/renderer占用 |
| 持久化 | JSON.NET原子临时写+替换、失败可见；只保存有界UI/采样偏好，不保存token、快照、无限历史 | 重启恢复；坏文件降级默认且提示；检查落盘无token；避免每次采样写磁盘 |

内存接口依据微软当前GetProcessMemoryInfo文档：Windows10/11只要求QUERY_INFORMATION或QUERY_LIMITED_INFORMATION；VM_READ是XP/Server2003要求。复用已打开查询句柄读取PROCESS_MEMORY_COUNTERS_EX的工作集/PrivateUsage，避免每帧约850次多余OpenProcess，且减少不必要的受限值。

## 6. 交付判定

必须同时满足：功能闭环真实、Token一致、错误可恢复、未增加自有协议、性能有实测、真实Electron E2E通过。完整矩阵见 `ACCEPTANCE.md` 的B系列；最终报告逐项标已通过/实际受限/未完成，不能把“已设计”写成“已实现”。逐进程网络吞吐仍需ETW等独立采集，不拿TCP/UDP连接替代；官方启动设置是可用真实入口，不声称本应用已编辑所有启动策略。
