# Qt 图标缓存

日期：2026-11-04。用户要求“图标需要做缓存”。本增量只完善现有 Qt 图标加载和绘制缓存，沿用真实 Windows 图标、既有 HTTP/PNG 接口、.NET 10/JSON.NET/CsWin32 与独立 Shell STA。下面合同覆盖 [APPLICATION-ICONS-ADAPTERS.md](APPLICATION-ICONS-ADAPTERS.md) 中已经退出活动实现的 React/Blob URL 细节。

## 问题与目标

当前 Qt 将“已经请求”集合与图像分开保存，超过512项时全清，导致热图标重新请求；无图标只靠逐项定时器移除请求标记，成功图标则不复核真实来源。异步请求完成后未主动调度下一批可见行。`Theme::icon` 每次重新解析 SVG、生成像素图，且 `icons.value(identity, Theme::icon(0))` 即使命中也先计算默认图标。目标是滚动、刷新和切页时复用已解码图标，按需有界加载，真实来源变化或暂时失败可以恢复。

## 已实际读取的成熟实现

2026-11-04 通过 GitHub 原始源码读取，HTTP 200；Qt v6.8.3 固定提交为 `c07c2d5a527a644d36e7853d55132ae38921682f`：

- [Qt QCache](https://github.com/qt/qtbase/blob/c07c2d5a527a644d36e7853d55132ae38921682f/src/corelib/tools/qcache.h)：`object` 经 `relink` 将命中对象移到最近使用端；`trim` 从另一端逐项淘汰，`insert` 先限制总成本。采用 Qt 公开 QCache 的有界、命中续用和逐项淘汰机制，避免自定义淘汰协议或整库清空。
- [Qt QIcon](https://github.com/qt/qtbase/blob/c07c2d5a527a644d36e7853d55132ae38921682f/src/gui/image/qicon.cpp)：108行附近使用 `QCache<QString, QIcon>` 保存可复用图标，351行附近通过包含图像身份和 palette 的键复用转换后的 pixmap。采用固定主题图标只构建一次、通过 QIcon 隐式共享复用的思路。本项目只支持现有浅色主题，不新增颜色、尺寸或暗色需求。
- [TaskExplorer ProcessModel](https://github.com/DavidXanatos/TaskExplorer/blob/9f3f95d22f07f759dd1e0114417529ba51decb01/TaskExplorer/GUI/Models/ProcessModel.cpp)：实际读取该固定文件，保持模型按真实身份关联数据、视图按需绘制的既有集成方式；本次缓存算法依据为上述 Qt 源码，不声称从该文件核验到图标 LRU。不复制 GPL 业务代码。

## 缓存与加载合同

1. Qt 会话内保留最多512条应用图标缓存；成功项和无图标/失败项都计入容量。采用 LRU 逐项淘汰，访问热项续用，不因累计访问超过512而清空全部结果。QIcon/QPixmap 在 GUI 线程创建、读取和释放，关闭窗口后随所属对象释放，不持久化业务行或图像到磁盘。
2. 缓存身份来源于既有 `kind` 和服务端认可的行 `id`；进程与详细信息使用同一进程 identity，历史中相同 identity 可复用同一图标。启动项和服务使用各自命名空间，不以显示名称、PID、裸文件路径或猜测的应用品牌合并不同来源。尤其不能忽略打包应用的 AUMID，仅凭 EXE 路径合并不同应用。
3. UI 可观察的来源变更（例如启动项命令/来源文件变化）应使对应条目重新验证；成功项最多60秒复核一次可见来源，首次成功后可15秒复核一次以等待后台元数据。不可见条目不定时发请求。现有后端 `path + mtime + AUMID` 缓存继续决定真实图像，不新增客户端任意路径/AUMID输入或图标协议；服务配置沿用既有15秒后台读取缓存。
4. 204、网络失败、不可解码 PNG 等结果至少15秒后才重试；复核失败保留上次成功图标并退避，不把失败转换为成功或假品牌。没有成功图标时使用已有通用图标，占位与行高不变。使用有界缓存中的时间状态安排重试，避免为每次失败持续累积独立定时器。
5. 全窗口最多2个应用图标请求进行中，相同缓存键的进行中请求合并；缓存命中不发请求、不再次解码 PNG。请求完成后继续装填当前可见行，滚动、筛选、切页和恢复连接后也可继续加载；后台任务不阻塞采样、GUI 绘制或既有写操作。
6. 请求与回调必须携带发起时的缓存身份；切页后旧回调只能更新它自己的缓存条目，不得把同名的另一类行图标覆盖。更新 DecorationRole 时核对当前模型身份及来源，保留搜索、排序、滚动、选中和展开状态。
7. `Theme::icon` 中现有有限种导航/默认图标按索引复用 QIcon，正常重复取用不重复解析 SVG/创建像素图。模型在缺少实际缓存图标时才取默认图标，命中路径不执行默认图标生成。复用 MASTER 的图标尺寸、颜色与占位，不增加设计 Token 或界面设置。

| ID | 场景与证据 |
|---|---|
| IC01 | Qt Release 与 .NET Release 构建成功；无新协议、JSON库或采集绑定，记录命令和退出码。 |
| IC02 | 超过512个缓存身份访问后容量仍有界，最近使用的热项继续存在；同键请求未完成时不重复发起。必要的纯缓存测试可用独立键验证算法，不模拟 Windows 业务数据。 |

| IC04 | 真实 Host→HTTP→Qt 中滚动、切页/返回、刷新和筛选继续装载可见图标；缓存热项复用，PNG正常解码，图标与当前行身份一致；无整库重载、无限请求或行高变化。 |
| IC05 | 失败条目在退避期不重复请求，成功图标复核失败时仍可显示；来源变化/到期可恢复。人工或组件可控错误分支与真实API成功证据分别记录，不将错误测试当成真实Windows来源成功。 |
