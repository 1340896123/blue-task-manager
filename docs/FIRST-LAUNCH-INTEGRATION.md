# 首次启动：替换标准任务管理器

> 2026-10-26 已启用入口免提示：正式桌面先读取真实入口，再决定是否创建首次对话框；`status === enabled` 且 `enabled === true` 表示当前目录已正常接管，静默保存首次选择完成标记，不显示或闪现提示，不发送 IFEO 写请求。此规则覆盖下文旧版“enabled 提供继续使用”的行为。

> 2026-10-26 最新已有入口接管合同见 [TASK-MANAGER-TAKEOVER.md](TASK-MANAGER-TAKEOVER.md)。首次提示遇到其他工具/特殊配置应明确替换后果，并提供前往设置接管现有入口的路径；不再永久禁用且宣称不可覆盖。该路径进入设置明确确认，不隐式提交 takeOver；取消最终恢复 Windows 标准入口，不恢复旧工具。以下冲突一律禁用是历史行为。

日期：2026-10-25。此增量扩展现有设置中的任务管理器入口，不改变原生接管合同；历史“只能在设置启用”由此覆盖，接管仍默认关闭，只有明确点击替换才允许写入。

## 用户目标与触发

第一次打开正式 Electron.NET 桌面时，用户能选择让 Windows 原“任务管理器”入口打开蓝域，或直接开始使用。标题为“替换标准任务管理器？”，主按钮为“替换标准任务管理器”，次按钮为“暂不替换”。不增加启动向导、二次确认或先勾选的系统开关。

- 仅在 `bootstrap.desktop === true`、偏好已成功读取且 `taskManagerPromptDismissed === false` 时检查首次提示资格。初次 GET 完成前不创建对话框；真实入口不是当前目录正常启用时才显示。普通浏览器、headless 后端不弹；偏好读取失败不以默认 false 抢先弹出，重读成功后再判断。
- GET 明确返回 `status === enabled` 且 `enabled === true` 时，静默调用现有偏好保存链将 `taskManagerPromptDismissed` 设为 true。当前目录由后端精确命令/入口状态判断，不能仅凭品牌、文件名或 `ownsDebugger` 跳过；`migrationRequired`、其他目录及过滤冲突仍进入既有提示。
- 新增用户级偏好 `taskManagerPromptDismissed:boolean`，默认 false；旧版缺少字段也为 false，升级后首次展示一次。它只记录是否已完成这次选择，不代表实际系统接管状态。
- “暂不替换”、关闭和 Escape 只保存该偏好 true，不发送系统接管写请求；之后可在“设置 → 任务管理器入口”启用或恢复。普通“恢复默认界面偏好”保留该标记，避免再次打扰。
- 成功替换并经后端读回后保存 true。保存失败须明确“选择未保存，重启可能再次提示”，不能把系统替换成功说成失败；用户可继续使用并从既有偏好提示重试。用户直接退出、尚未选择或替换失败时不标记完成。
- 已正常接管的静默保存失败沿用偏好保存错误提示，不宣称已落盘，不因此弹出替换对话框；后续启动若入口仍为同一正常启用状态，继续静默跳过并尝试保存。识别与保存过程不调用系统入口 POST。

## 对话框信息与真实状态

沿用既有原生 `dialog`、Windows 蓝色按钮、共享焦点管理和 Token。正文用简短段落说明：任务栏右键“任务管理器”、Ctrl+Shift+Esc 等入口将打开蓝域；影响当前计算机的所有用户；以后从系统入口启动时 Windows 会请求管理员授权；可在设置取消；完整程序目录应固定且其他使用账户可读取，移动或删除前先取消接管。可折行显示真实程序路径。无营销插画、渐变或新视觉体系。

显示前通过既有 GET 读取 IFEO 真实状态，初次读取期间对话框保持未创建。首次 GET 失败或返回未知状态后显示既有错误恢复提示；在已打开对话框中重新读取时，保留对话框并禁用替换按钮，显示读取状态。读取失败保留明确错误、“重新读取”与“暂不替换”，不把 unknown 视为 disabled 或已接管。

| 实际状态 | 首次提示行为 |
|---|---|
| disabled 且 canEnable/canWrite/executableAvailable 均满足 | 主按钮允许替换；点击一次直接向既有 POST 提交 enabled:true 与当前 expectedRevision |
| enabled 且 enabled:true | 不创建对话框，静默保存首次选择完成；不重复写注册表 |
| migrationRequired | 明确“旧接管需要修复”，提供去设置处理；首次主按钮不能隐式提交 repair:true |
| conflict | 展示后端冲突原因与替换后果，提供“前往设置接管现有入口”；首次提示不隐式提交 takeOver |
| unavailable、无写权限或文件不完整 | 展示对应真实原因，替换禁用，允许重新读取或暂不 |

提交期间禁用重复提交和关闭，显示“正在替换并核验…”。POST 失败保留对话框、具体原因并重新 GET；409/写后状态未知不自动重试、不报成功，用户重新核验后再决定。所有请求复用同源 HTTP、令牌与 Origin 保护，不接收任意路径或注册表位置。

## 技术与偏好合同

后端 `UiPreferences` 增加末尾可选 bool，JSON.NET 原子保存与 64KiB 限制不变；前端集中类型和默认值同步。偏好完整对象的常规更新、窗口状态保存、采样周期保存均须保留标记；重置界面偏好只重置界面字段。渲染器不直接读写注册表，不增加接口或原生绑定，复用 `TaskManagerIntegrationService.Read/Apply` 的固定 HKLM64 IFEO、精确自有值判断、修复限制、revision 和读回保护。
